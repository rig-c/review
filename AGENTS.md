# review

A standalone human inspection and structured feedback app. Read README.md, docs/REVIEW_PACKAGE.md and docs/DESIGN.md before changing the delivery contract.

- Work here; do not edit rigc, parts or play core repositories as part of review changes.
- Keep supplied source assets and compiled models immutable. The producer writes motion in scratch; review never writes the package's motion.json or its `animations_from` file: motion edits (idle tracks, blink, retarget flags and pose maps, and the timeline's keyed ops on a scratch copy of `motion.animations_from`, #235) are data the installed producer builds into a scratch build, and a labelled preview before Apply is never recorded or submitted. Store feedback separately, bound to package identity, revision and actual input hash. Opening a package never approves it.
- All package assets must remain inside the package directory, with literal portable paths and no symlink escape. Never execute a manifest command or fetch a remote asset on its behalf.
- Playback uses the published `@rig-c/play` API. A loaded model is not proof of the upstream compiler's gate. State source provenance and missing capabilities honestly.
- View, Rig, Playback and Feedback are sections of one inspection workspace. Motion changes reach the producer as data (config patch, pose map, flags, keyed ops on a scratch copy of `animations_from`) and come back as a scratch build; this app never writes a source key. Do not label placeholders as working editing tools.
- The chest-region editor and Edit Mesh are a precision instrument for detail that cannot be said in words: the loop is "point → rebuild → watch → repeat → submit" (issue #99). Review builds no mesh itself. Apply · Rebuild runs the installed producer (`rig-parts`, found in the nearest `node_modules` from the package, then from review's working directory; refused by name when absent, never installed by review) as a child process on the user's own designation, into a scratch build under the review state directory, never into the inspected package, and reloads that build in place. A target the producer has no operation for refuses by name. The last applied inputs and the producer's line go into the draft and the submitted feedback, so the AI receiving the review can rebuild exactly that state.
- The interface ships in English and Korean together. A change to visible text updates `web/catalog-en.ts` and `web/catalog-ko.ts` in the same PR, and screenshots and eye checks cover both languages. Text a reviewer wrote, feedback payloads and exported Markdown are never translated.
- Require same-origin JSON mutations, a loopback-only server, bounded payloads and no arbitrary filesystem endpoint.
- Run focused tests for path/state boundaries. Use the global nova-run skill for full test/build/typecheck bundles.
- README is for deciding and getting a first result: what the package is, install, one first run with output, one line per panel or command with a link, and links. A feature PR adds at most one line. Put flag lists, refusal catalogues, dated or machine-specific figures, version history and development details in reference docs; license text stays behind a pointer. Move text without losing it, retain inbound heading stubs, and repoint content tests. Ship linked reference docs in package.json `files`, or use absolute GitHub URLs. Run `bun run check:readme` and `bun test tests/readme.test.ts`: the fixed 800-word cap (#224: 701 post-cut words + 10%, rounded up to 50, below the earlier 2,500 limit), heading allowlist and dated-phrase/table-date refusals are proved by named planted mutants. (Naru, 2026-10-30)
- 🚫 **Never re-implement an existing module. This is a hard rule, not a preference.** Before writing a viewer, viewport or camera control, renderer, overlay, parts composite, form, panel, field helper, catalog helper or route in `web/` or `src/`, find the existing one and import it. If an existing module almost fits, extend it in place and keep its callers' tests green. Do not write a sibling. New code that does what an existing module already does is a defect, whatever its tests say, and it is not merged. If nothing fits, the PR body carries a `## Reuse` table: each new function over 10 lines in `web/` or `src/`, the closest existing module (`file:line`), and why that module could not be used or extended. "None" is accepted only when the tree has no such module. Measured on 2.8.0: `web/job-session.ts` (2,521 lines, the live job page) imports none of `viewport-pair`, `view-controls`, `viewport-controller`, `rig-overlays`, `parts-render`, `interview-panel` or `stage-comments`, and re-implements a viewer, a parts grid and the interview form inline. The owner reads the result as duplicate code, and it cost the tokens to write it twice. Screen work also starts from an HQ screen plan posted on the issue; a lane builds from that plan and does not design the screen. (Roa, 2026-11-09)
- Use Conventional Commits in English. Agent-authored commits and final squash commits carry the authoring agent's own `Co-Authored-By` trailer; this file names no single agent. Parent agent handles Git landing; execution agents do not run Git.

## Code Review Rules

- People drive the Review UI while agents use semantic review-cycle commands (`publish`, `ask`, `next`, `close`) and downstream consumers directly fetch finalized acts. Never build or carry internal Review state, picks (`rig-review/interview-picks@1`), verdict (`rig-review-parts-verdict/2`), or applied-evidence files from an agent to bypass the active review cycle, while preserving legacy contract references in existing docs and fixtures.
- Pair every visible copy change in `web/catalog-en.ts` and `web/catalog-ko.ts`, and place machine refusal codes, templates, and identity strings as matching entries in both catalogs instead of adding `WEB_STRING_EXEMPTIONS` in `web/i18n.ts`. Run `tests/i18n.test.ts` whenever a change adds a new `web/` file or touches visible copy or catalog entries.
- Keep test-only packets to the ordinary test and its declared inputs, backed by the test exit code, output, and artifacts, plus any Nova receipt. The CI runner and pool own transport and admission, so runner sessions must not add duplicate snapshot-count, admission, or classifier guards.
- In a fresh worktree, a single frozen-lockfile install (`bun install --frozen-lockfile`) before the first test is declared setup. Stop and report if `package.json` or `bun.lock` would change, if `--force` would be required, or if an import remains missing after install, and never use `NODE_PATH` workarounds. Run focused non-browser tests locally, send browser, headless, and render validation to ordinary Nova except an explicitly authorized exclusive Apple-hardware timing measurement, use the global `nova-run` skill when a full test, build, and typecheck bundle is required, and let PR CI run acceptance suites without duplicate full runs in the runner session. (Jinni, 2026-11-07)
- The Review Tower independently reviews runner PRs, reads their single AI review, posts `LGTM #N at <SHA>` on the exact head, merges with `--match-head-commit`, and confirms main is green. HQ signs cross-repository or cross-tower dependency work, public contracts, APIs or exports consumed elsewhere, C-series revisions, and release PRs. For other work the Tower resolves PR rulings and sends HQ a landing report with the PR, merge SHA, verification table, rejections and STOP status. (Naru, 2026-11-07)
- Flag as P1 any added code that re-implements a module the tree already has (a viewer, viewport control, renderer, overlay, composite, form, panel or helper), and any PR that adds a function over 10 lines in `web/` or `src/` without a `## Reuse` table naming the closest existing module and why it could not be used. Check the table against the tree, not against the PR's word. (Roa, 2026-11-09)
